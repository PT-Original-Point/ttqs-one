# TTQS ONE R5.1 外部稽核裁決與施工修正

日期：2026-08-14
基準：main `e9c86b784626b5a7190c527c40c4f598e6a1fe4a`
狀態：施工候選；PROD／REAL 禁止

## 一、裁決原則

本文件不是把外部稽核報告直接升格為規格，而是把每一項主張分成「採納、部分採納、拒絕、延後」，只有能被官方文件、目前儲存庫狀態或可重現工程事實支持的內容才進入 R5.1。

核心戰略不變：Google Workspace 先維持為 MVP 主平台，但正式資料生命線、權限域、部署生命線及評核快照必須可驗證；Google 限額與試算表弱點以架構避開，不以宣稱取代實測。

## 二、立即採納的高價值修正

### 1. 公開高流量表單不得依賴每筆送出觸發完整處理

正式需求調查的權威候選入口改為「Google Forms 原始回覆 → 批次擷取 → 不可變收件副本 → 業務處理」。每筆送出觸發只保留給 TEST 示範或經容量驗證的低流量內部用途。

正式收件以 `form_id + response_id` 作唯一來源身分；時間戳記只作查詢水位，不作唯一鍵。

### 2. Forms API 水位線必須有重疊視窗與分頁完成條件

批次擷取必須：

1. 從「上次高水位減重疊視窗」重新讀取。
2. 走完所有分頁。
3. 以 `response_id` 去重。
4. 每一頁資料先持久化。
5. 完成集合對帳後才推進高水位。

不得只保存 `last_processed_timestamp` 就向前移動。

### 3. 凍結唯一資料來源層級

- L0：Google Forms `responseId`，外部提交來源。
- L1：收件原始副本，保存標準化原始內容及來源雜湊。
- L2：核心營運資料投影。
- L3：TTQS 佐證關聯。
- L4：發布後評核快照。

對帳採 ID 集合，不只比較總數。

### 4. 批次程序只短暫持鎖

全域鎖不得包住整個批次運算。鎖只用於：

- 領取待處理工作。
- 比對租約／提交權杖。
- 提交最終狀態。

領取後的資料解析、驗證、計算應在無全域鎖狀態進行。每筆工作必須有租約持有人、租約到期時間及提交權杖，避免逾時工作被接手後又回來覆寫。

### 5. Script Properties 只存小型設定／水位，不存整個佇列

工作內容、失敗歷史、重試狀態與長期稽核資料必須落在結構化資料層；Script Properties 只保存小型設定、目前水位與必要租約資訊。

### 6. 個資必須有真正的權限隔離

「個人資料保管區」不能只是一張不同名稱的工作表。R5.1 要把個資權限域視為獨立資產，至少必須做到：

- 評核快照不含直接識別資料。
- 個資映射表不進評核包。
- 個資資料夾或獨立 Shared Drive 採受限存取。
- 表單與其回覆試算表權限各自稽核。
- 任何新角色權限邊界變更先交人工核准。

是否最終採「獨立 Shared Drive」或「Shared Drive 受限存取資料夾」，在正式 REAL 收件前以實際 Workspace 權限測試決定；不能只靠資料夾名稱宣稱物理隔離完成。

### 7. Hash chain 保留，但不得冒充不可竄改證明

既有 SHA-256 鏈保留作「偵測鏈內修改」。正式版另建立外部錨定：至少在每次正式發布時輸出 ledger root hash、snapshot root hash、source commit SHA、部署身分及時間，寫到不同權限域的發布紀錄或不可覆蓋交付物。

### 8. 離線評核不得假設雙擊資料夾內 index.html 一定正常

正式離線評核優先採「單一自包含 HTML + 必要遮罩附件」；不得依賴 Service Worker 才能啟動。所有正式離線包要在 Safari、Chrome、Edge 至少各完成一次離線開啟驗收。

### 9. 評核 Portal 與離線包的安全能力分開描述

線上 Portal 可具短效驗證、到期、撤銷及存取紀錄；離線包一旦交付即不能遠端撤銷，因此必須靠版本、交付管制、遮罩、必要性最小化及現場回收治理。兩者不得描述成同等安全。

### 10. 系統身分與業務操作者歸責分開

即使網頁以存取者身分執行，仍不能只靠 Google 最終寫入者判定「誰核准」。關鍵操作至少記錄：操作者身分、工作階段、動作、目標、變更前後雜湊、伺服器時間、請求編號、部署版本與核准理由。

A／B／C 可以具有相同營運權限，但不共用帳號。

### 11. TEST 部署採受控 ref 自動觸發

TEST 部署改由 `deploy/test` 分支推送自動觸發。部署工作流必須：

- 只接受 `refs/heads/deploy/test`。
- 該 SHA 必須已存在 `main` 歷史。
- 使用 TEST Environment 與 TEST 專用 secrets。
- 部署前重新跑完整 verify。
- 部署前後都驗證 clasp 發布集合。
- 使用 concurrency 防止兩次 TEST 部署同時進行。
- 記錄來源 SHA 與環境。

PROD 不採此自動模式；PROD 保留人工正式核准。

## 三、部分採納

### 1. LockService「最多只能等 30 秒」

不採納為 Google 硬限制。官方 `waitLock(timeoutInMillis)` 的逾時值是呼叫端提供的毫秒數，30 秒只是官方範例。真正值得採納的是「不要長時間持有全域鎖」。

### 2. PWA IndexedDB 七天一定被清除

不採納為普遍硬規則。Safari／WebKit 的追蹤防護確實存在七天無互動後清除可由指令碼寫入儲存的情境，但安裝到主畫面的獨立 Web App 有不同處理。工程結論仍是：瀏覽器本機儲存不可當唯一真實來源；斷網事件必須有同步狀態與人工備援。

### 3. `navigator.storage.persist()` 可徹底保證不被清除

不接受「保證」說法。可以作增強措施，但正式資料不可只存在瀏覽器。第一期現場仍以單一主要寫入裝置 + 紙本／人工備援 + 恢復同步為主。

### 4. 離線多設備衝突用「最後寫入者勝」

只部分採納。原始事件全部保留是正確的，但出勤／請假／遲到等狀態不可只用時間戳自動決定真實事實。出現衝突時進入「待人工核定」，保留兩筆原始事件與最後核定者。

### 5. `drive.file` 一律無法支撐 Shared Drive 證據庫

過度簡化。`drive.file` 的確是檔案級授權，適合應用建立或使用者明確分享／選取的檔案；若系統要自動掃描既有整個證據庫，就可能需要更廣權限或不同資料治理。R5.1 先做「檔案授權模型測試」，不直接把所有 Drive scope 擴大。

### 6. 13 個 `.gs` 應立即改成單一編譯檔

先不做。現在 13 檔白名單是已驗證的供應鏈防線。後續前端／模組數明顯增加時，再評估「原始碼多模組、部署產物固定集合」。不為了理論潔癖提前重構。

## 四、拒絕或延後

### 1. 現在就換 Cloud Run／PostgreSQL

拒絕。第一期需求調查約 600 人、單班約 20–30 人，沒有證據支持現在換平台。只有真實 Google TEST 壓測顯示 Apps Script／Sheets 達到安全線時，才啟動背景處理器外移。

### 2. 用固定「5 班／2 萬列」作遷移門檻

拒絕固定數字。遷移依實測：批次延遲、鎖等待、每日觸發時間、對帳時間、恢復時間、錯誤率及維運成本決定。

### 3. 為了 TTQS 先建立大量紙本

不採作一般 TTQS 要求。紙本只在外部方案／法規／正式文件本身要求時保留。數位原件具可靠身分、版本與核准軌跡時可作 TTQS 佐證。若未來參加產業人才投資方案，學員出勤則另依該方案最新規定建立親簽原始紀錄。

### 4. 以 GPS 作簽到必要證據

拒絕。第一期沒有必要蒐集 GPS；這與最小必要個資原則衝突。電子簽到可作營運輔助，但不自行增加定位蒐集。

### 5. 將本機 10,000 筆測試當 Google 容量證明

拒絕。永遠標記為本機資料處理模型；真實 Apps Script／Sheets 壓測另立 Gate。

## 五、產投方案出勤的處理

外部稽核指出產投班需要學員親自簽到退，這項方向有官方歷史訴願案例支持：學員未親自簽名而以姓名章代替，曾導致補助不予核發；相關規定要求上課前親自簽到、下課後親自簽退，並以中文正楷全名簽名。

因此若本協會未來正式採產業人才投資方案辦班，系統設計採「紙本親簽原件為方案出勤權威證據 + 電子系統作即時營運與數位索引」，並在每次申請前重新核對當年度最新作業手冊。這項規則不直接套用到所有非產投 TTQS 一般課程。

## 六、R5.1 重排施工 Gate

### Gate A：資料生命線

- Forms 唯一來源身分。
- responseId 去重。
- 水位線重疊與完整分頁。
- ID 集合對帳。
- schema version／欄位簽章。
- 個資權限域。
- 備份與恢復規格。

### Gate B：執行核心

- 環境政策。
- 短鎖 claim／commit。
- lease + fencing token。
- bounded retry。
- checkpoint。
- append-only attempt history。
- 外部 hash anchor。

### Gate C：真實 TEST runtime

- 100／600／1200／3000。
- 同時間戳邊界。
- 分頁中斷。
- lock contention。
- stale worker takeover。
- schema drift。
- ID 集合對帳。

### Gate D：正式需求調查資料契約

- 匿名問卷。
- REAL／PII 分界。
- 課程候選分析。
- 人工開課核定。

### Gate E：繁中操作介面與二樓現場

- ABC 控制台。
- 主要寫入裝置 + 備援裝置。
- 30 裝置現場 Wi-Fi 壓測。
- 斷網與恢復同步。

### Gate F：評核與佐證

- Evidence Graph。
- 去識別化。
- 評核快照。
- 外部 hash anchor。
- 線上唯讀 Portal。
- 單檔優先離線包。
- 9/1 顧問語義校準。
