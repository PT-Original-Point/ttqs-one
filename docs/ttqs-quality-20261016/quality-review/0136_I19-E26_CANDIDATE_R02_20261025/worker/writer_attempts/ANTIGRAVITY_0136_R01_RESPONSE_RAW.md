# DOCX 0136《公益活動、獎項與學校合作原件驗證登錄表》作業手冊與登錄管制規範

---

## 1. 快速使用指南與適用範圍

### 1.1 文件定位與行政人員核心職責
本手冊與登錄表專供本協會行政人員、文件管制人員及查核主管於日常營運中，執行勞動部勞動力發展署「人才發展品質管理系統」（TTQS）指標 19 高標準佐證之收件、原件保全、真實性核驗、分類登錄、調閱管制與審查流轉作業。

本文件為**原件驗證與佐證登錄之管理作業工具（Operational Verification Register）**，其法律與評核定位為「管制程序與佐證履歷」，**絕非**主張本協會已達成特定社會成效、獲頒特定獎項或完成產學研發之實質成果報告書。未經本手冊規定之完整雙重覆核並取得合規原件前，任何登錄項目均不得於外部評核中作為已驗證佐證提出。

### 1.2 登錄時機與建檔要件
行政人員應於接獲下列任一情事之第一手原始憑證或權利證明時，於 24 小時內啟動登錄程序建立管制案號：
1. 外部主辦單位出具之社會公益活動參與、協辦或辦理確認原件。
2. 公民營機構正式頒發之獲獎公文、獎狀、獎座或官方得獎清冊正本。
3. 大專校院或學術研究機構正式簽署之產學合作協議、研發成果社會化驗收或成果擴散證明文件。

> [!IMPORTANT]
> **「登錄不等於採計，主張不等於佐證」核心禁令**  
> 單純將事項填入登錄表，僅代表行政收件之事實，**不具備任何佐證真實性效力**。嚴禁在未檢附法定原始憑證、未查驗出具單位主管權限及未分離「參與事實」與「成效量化」之情況下，逕行認定佐證成立。在實體原件未經獨立驗證前，該筆紀錄之狀態僅能歸入審查中或示範狀態。

### 1.3 歸檔前查核三步驟（Three-Step Pre-filing Review）
行政人員於將任何佐證文件入庫與結案前，必須嚴格執行下列查核：
1. **第一步：權限與格式檢驗（Integrity & Authority Check）**  
   確認文件出具機關具備法定代表權，簽署人具備職務授權；紙本查驗用印與浮水印，電子檔計算並比對 SHA-256 雜湊碼，確認檔案無塗改、無抽頁且具備時間戳記。
2. **第二步：協會角色與成效獨立分離查驗（Role & Outcome Decoupling Check）**  
   嚴格區分「外部活動存在事實」、「本協會實質承擔角色」與「聲稱之社會量化影響」。任一維度缺乏直接第一手佐證者，不得合併推定，成效數據缺乏分母與計算公式者一律標註為 `UNKNOWN`。
3. **第三步：個人資料與公開界線審查（Privacy & Disclosure Clearance）**  
   全面審查受保護之個人資料（身分證字號、聯絡電話、病歷、個人帳戶等），執行去識別化遮罩；涉及未成年人、弱勢族群受助清冊者，未取得法定同意書前嚴格列為內部限閱，禁止對外公開。

### 2.1 官方規範出處與原文字句

### 2.2 官方文件屬性定位與禁止自評宣告
1. **參考佐證本質**：上述官方條文為評核委員於評定指標 19 是否達到高標準表現時之「參考佐證範例（Reference Evidence Examples）」，並非強制要求受評單位必須同時、無遺漏地全數具備該三類佐證。
2. **禁止宣稱全數具備**：本協會嚴禁在欠缺真實原件之情況下，對外宣稱已全數涵蓋公益、獎項與產學研發社會面三項要素。
3. **嚴禁自我評分**：本登錄表僅作為文件收受與真實性管制之後勤工具，**本會人員嚴禁在本文件或任何衍生表單中自行標註、評定或預測 TTQS 評審得分或等級**。

## 3. 收件、原件保全與保管鏈作業程序（SOP）

```
[原始憑證送達] 
       │
       ▼
【步驟一：收件確認與不可變編號賦予】── 產生唯一 RECORD-YYYY-NNN (禁止重複/刪除)
       │
       ▼
【步驟二：實體保全與數位雜湊鎖定】 
  ├─ 實體紙本：無酸檔案袋封存、防火防潮箱、雙人雙鎖管制
  └─ 電子檔案：WORM 唯讀儲存、即時計算 SHA-256 (64位元十六進位)
       │
       ▼
【步驟三：分級授權儲存與中繼資料分離】
  ├─ 機密儲存區 (RESTRICTED)：完整原件、未遮蔽個資、雜湊對照
  └─ 公開登錄區 (PUBLIC_METADATA)：去識別化代碼、脫敏摘要、驗證狀態
       │
       ▼
【步驟四：保管鏈移轉全程即時記錄】── 凡調閱、移轉、複印、歸還皆須雙人簽章
```

### 3.1 步驟一：收件確認與不可變紀錄編號賦予
1. 行政人員接獲佐證案件時，應先確認交付之形式（紙本正本、電子檔案、掃描影本）。
2. 每筆申請案由系統自動編發不可變紀錄編號（Immutable Record ID），格式統一為：
   $$\text{REC-0136-YYYY-NNNN}$$
   （例如：`REC-0136-2026-0001`）。編號一經生成，即成為該佐證於本會生命週期之永久識別碼，嚴禁修改、重複指派或於刪除後遞補。

### 3.2 步驟二：實體保全與數位雜湊值鎖定
1. **實體紙本原件保全**：
   - 收件後立即檢視原件外觀，拍照記錄收件現況，不得於原件上加蓋任何收件章或書寫文字。
   - 將原件置入專用無酸聚酯透明保護套內，加註標籤卡（僅記載 Record ID），收納於專用保全防潮防火保險櫃（存放等級 Tier-3）。
   - 保險櫃實施實體雙人雙鎖管制（行政秘書持鑰匙，文件管制主管持密碼）。
2. **電子檔案保全與 SHA-256 計算**：
   - 凡以數位方式收受之檔案（PDF、TIFF、數位簽章檔），接收後立即移入 WORM（Write Once Read Many）唯讀儲存伺服器。
   - 於接收端終端機執行 SHA-256 密碼編譯雜湊計算，取得 64 位元十六進位雜湊碼，並立即登入管聯表。
   - 電子檔命名規則：`[Record_ID]_[YYYYMMDD]_[Document_Class]_[SHA256_Prefix8].ext`。

### 3.3 步驟三：分級儲存與公私中繼資料分離架構
為兼顧評核查驗需要與資訊安全隱私保護，本會實施嚴格之儲存位置分離架構：
1. **受限實體儲存區（Restricted Original Storage）**：
   - 儲存路徑：`SECURE_VAULT://TTQS/2026/I19-E26/[Record_ID]/`。
   - 存放內容：完整高解析度原始掃描檔、原始合約紙本、含個資之名冊、出具單位內部聯絡人電話及通訊公文。
   - 存取限制：僅限資深文件管制員與理事長授權之專案負責人具備讀取權限。
2. **公開去識別化中繼資料區（Sanitized Public Metadata）**：
   - 儲存路徑：`PUBLIC_REPO://METADATA/0136/`。
   - 存放內容：登錄表公開欄位、遮蔽個資後之摘要、公開宣告字樣、SHA-256 驗證碼、驗證狀態。
   - 存取限制：供一般行政人員作業、內部稽核及評核委員現場查對目錄。

### 3.4 步驟四：保管鏈（Chain of Custody）移轉作業規範
原件實體與受限電子檔案之任何移轉、借調、送交公證或抽印，必須即時登錄於保管鏈專用紀錄表：
1. **移轉登記要件**：每次調閱必須載明「申請調閱人身分」、「核准主管職稱」、「調閱目的」、「移出精確時間（年月日時分）」、「預計歸還時間」及「調閱時原件狀態檢核」。
2. **雙人點交原則**：原件出庫與入庫，必須由保管員與調閱人當面清點頁數、檢視封套完整性，並於紙本與電子雙軌保管鏈日誌完成親筆簽署（或數位憑證簽章）。

## 4. 三大佐證類別獨立核驗流程

```
【三大佐證類別獨立核驗流程】
  │
  ├─►【A 類：社會公益活動】
  │     ├─ 階段一：主辦單位存在性與活動真實性核驗 (非自導自演)
  │     ├─ 階段二：本協會實質角色與投入憑證核驗 (非掛名、非純學員參與)
  │     └─ 階段三：社會成效憑證獨立核驗 (受益分母/計量憑據，無則標註 UNKNOWN)
  │
  ├─►【B 類：公民營單位獎項】
  │     ├─ 階段一：頒發機構法人地位與遴選簡章核驗 (非付費購獎、非參賽證明)
  │     ├─ 階段二：受獎主體與得獎名冊官方核驗 (主體為本會，非個人私德)
  │     └─ 階段三：表揚事蹟與評選基準公開紀錄核對 (評核週期內有效)
  │
  └─►【C 類：學校產學或研發成果社會面】
  │     ├─ 階段一：合作大專校院與正式合約效期核驗 (非純 MOU、具法人印信)
  │     ├─ 階段二：本協會實質產學研發工作產出核驗 (驗收報告、工作分配紀錄)
  │     └─ 階段三：社會面影響與應用成效分離核驗 (非商業銷售，獨立衡量社會效益)
```

### 4.1 類別 A：社會公益活動核驗路徑（Social-Benefit Activity）
社會公益活動核驗嚴格拆解為三個獨立檢查點，禁止以單一感謝狀混充全案成效：
1. **階段一：活動真實性與主辦機構核驗**  
   - 查驗活動是否由具合法立案資格之非營利機構、政府機關或合法團體主辦；非本會自辦之自導自演活動。
   - 核驗文件：主辦單位立案證書影本、對外公開發布之活動章程、公函或活動官方專屬網站紀錄存檔。
2. **階段二：本會實質參與角色核驗**  
   - 嚴禁以「本會學員個人自發參與」或「會員個人志工服務」虛充為本會組織行為。
   - 必須提出載明本會法人全稱之「共同辦理合約書」、「主辦單位指定邀請公函」、「經費分攤收據」或「志工指派派令與出勤紀錄」。
3. **階段三：獨立社會效益與量化成效核驗**  
   - **成效分離原則**：活動總服務量不等於本會貢獻量。
   - 受益人數、物資發放量、服務時數必須具備原始簽收單冊、第三方法人出具之成效結案報告或客觀點交清冊。
   - 缺乏具體量化統計分母（Denominator）或無獨立第三方出具憑證者，成效數值欄位一律填寫 `UNKNOWN`，僅得登錄為定性參與活動，禁止宣稱未經證實之量化效益。

### 4.2 類別 B：公民營單位獎項核驗路徑（Public/Private Award）
防範付費購獎、未得獎之入圍參賽、或個人榮譽移轉為協會績效：
1. **階段一：頒發機構公信力與獎項真偽核驗**  
   - 查驗頒獎機構是否為主管機關、依法設立之法人組織或公信機構；嚴禁採計「付費即得獎」、「未經客觀遴選之商業宣傳獎項」。
   - 核驗文件：公開評選簡章、評審團名單、頒獎典禮官方手冊或主管機關獎勵核定函。
2. **階段二：得獎主體資格查核**  
   - 獎狀、獎座或得獎證書上載明之受獎主體，必須明確為「本協會（法人全稱）」或本會直屬訓練單位。

## 6. 判定標準、例外條件與流轉規則

```
[新件登錄 / PENDING_SOURCE]
       │
       ├─► 查核不合規 / 偽變造 / 非本會主體 ──►【REJECTED】(封存備查，永久不可採計)
       │
       ├─► 涉及高敏個資 / 未授權揭露 ──────►【HOLD_PRIVACY】(遮蔽補正後重審)
       │
       ├─► 取得第三方公開名冊 / 缺原件 ────►【VERIFIED_SECONDARY】(僅限間接背景佐證)
       │
       ├─► 取得第一手原件 / 雙重核驗通過 ──►【VERIFIED_PRIMARY】(正式採計列入卷宗)
       │
       └─► 系統測試 / 範本演練 ──────────►【SAMPLE_ONLY】(不可採計為真實成果)
```

### 6.1 判定決策權限與核決層級（Authority Matrix）
為維持客觀性，本會實施登錄、核驗、判定三權分立制度：
- **登錄人員（行政秘書 / 文件專員）**：負責接件登記、掃描雜湊、建立案號，初始狀態一律為 `PENDING_SOURCE` 或 `SAMPLE_ONLY`。
- **初核人員（品保工程師 / 內部稽核員）**：執行向外部機構之查證電話/公文照會、雜湊校對、角色與成效分離檢驗，填寫核驗意見。
- **終審主管（文件管制經理 / 秘書長）**：具備判定 `VERIFIED_PRIMARY`、`VERIFIED_SECONDARY`、`HOLD_PRIVACY` 及 `REJECTED` 之最終核決權。重大爭議或退件駁回案件，須報備理事會備查。

### 6.2 升軌與降軌流轉條件
1. **升軌條件（Promotion to `VERIFIED_PRIMARY`）**：
   - 必須同時符合五大要件：① 取得實體用印或具合法電子簽章之原始憑證；② 經出具單位官方管道查證屬實；③ 協會實質角色憑證完備；④ 社會成效數據具獨立佐證或客觀記載為 `UNKNOWN`；⑤ 個人資料已合法取得授權或完成物理去識別化。
2. **降軌與暫緩條件（Transition to `HOLD_PRIVACY` or `PENDING_SOURCE`）**：
   - 原件核驗通過，但發現附件之簽到冊含身分證字號與病歷個資且未獲當事人授權者，立即降軌為 `HOLD_PRIVACY`，封鎖調閱通道。
   - 外部主辦單位組織重整、查證管道暫時中斷、或協議書補充附約待簽核者，移入 `PENDING_SOURCE`，設定限期補正。
3. **駁回條件（Transition to `REJECTED`）**：
   - 逾越補正期限（通知後 30 個日曆天內）仍無法提出第一手原件或客觀佐證者。
   - 憑證有塗改、偽變造痕跡，或出具單位正式否認發布該項事實者。
   - 獎項或合作係由商業仲介付費購得，無客觀評審或產學研發事實者。

### 6.3 示範資料隔離紅線（SAMPLE Non-Counting Boundary）
- 系統內任何標記為 `SAMPLE_ONLY` 之紀錄，系統後端強制寫入旗標 `IS_SYNTHETIC=TRUE` 及 `EVALUATION_ELIGIBLE=FALSE`。
- 產出正式評核清冊時，報表產生引擎強制自動過濾所有 `SAMPLE_ONLY` 項目。**嚴禁將示範案例之任何文字、數字或代碼，引用為本協會實際受評之成果數據**。

### 8.1 邊界界限與禁令規範（Negative Neighbors Control）
行政人員於受理文件時，必須依佐證本質精確歸入相應交付文件，嚴禁挪用與相互混淆：
1. **禁絕挪用 0135（市場與顧客價值創造）**：
   - 產學合作衍生之商業產品銷售額、市場佔有率提升、顧客滿意度指數等純商業效益數據，屬於 `DOCX 0135` 之管轄範圍，**嚴禁將商業營銷數據填入本登錄表**。
2. **禁絕以 0137（正面媒體報導）取代實體原件**：
   - 報章雜誌、網路新聞或電視台對本會公益活動、獲獎或產學研發之採訪報導，其本身屬於 `DOCX 0137` 正面報導清冊。
   - **媒體報導僅能作為「佐證輔助檢索線索（Corroborating Locator）」，絕對不得代替主辦單位證明、獎狀正本或產學合約實體原件**。無實體原件而僅有新聞報導者，本登錄表一律判定為 `PENDING_SOURCE`。
3. **禁絕挪用 0133（訓練班次人次）與 0134（會員名冊與會費）**：
   - 本會例行收費開班之參訓人次與學員時數，屬於 `DOCX 0133`，不得灌入公益活動計算；本會會員名冊與會費繳納收據，屬於 `DOCX 0134`，不得作為公益捐助或社會回饋之主張。

### 8.2 共通主鍵（Shared Event-Project Key）防重機制
為防範同一活動或專案在不同佐證文件間重複申報或重複計算績效，實施全會共通主鍵管制：
1. **主鍵結構**：`[類別代碼]_[年度]_[專案識別縮寫]`（例如：`PRJ_2026_SENIOR_WELLBEING`）。
2. **查重檢核程序**：
   - 行政人員於建立新紀錄時，系統自動比對 `event_project_key`。
   - 若發現相同專案主鍵已於 `DOCX 0133` 申報為收費訓練班次，則本表禁止將該班次重複登錄為「公益免費活動」。
   - 若同一獲獎事蹟同時獲平面媒體報導，該媒體報導在 `DOCX 0137` 必須綁定同一專案主鍵，但其評核分數與佐證本體歸屬於本表原件，禁止於雙邊重複計算佐證數量。

## 9. 個人資料保護、存取權限與保存調閱管理

### 9.1 個人資料最小化與法令遵循
本會執行佐證原件驗證，嚴格遵循《個人資料保護法》及 ISO/IEC 27001 資訊安全管理規範：
1. **最小化收集原則**：佐證登錄表之公開欄位完全禁止記載受助者、學童、病患或個別學員之任何敏感個人資訊。
2. **法定處理基礎**：活動簽到冊或受獎名冊若包含自然人姓名，必須取得當事人簽署之「TTQS 評核佐證使用同意書」；若屬不可抗力無法取得者，行政人員必須於入庫前執行去識別化處理。

### 9.2 遮蔽規範與去識別化實施標準（Redaction Rules）
凡列入受限儲存區與公開展示區之文件，其涉及個資部分一律依下列標準執行不可逆遮蔽：
- **身分證字號 / 護照號碼**：僅保留首碼英文字母及末三碼數字，其餘以星號遮蔽（例：`A12****789`）。
- **聯絡電話 / 行動電話**：遮蔽中間四碼（例：`0912-***-456`）。
- **住址資訊**：僅保留至縣市及鄉鎮市區，路名及門牌號碼全數遮蔽。
- **相片與人臉識別**：公益活動現場紀實照片，除非當事人為本會公開指派之發言人或專職人員，一般民眾與未成年長者臉部一律進行高斯模糊化處理。

## 10. 待補件追蹤、審查判定彙總與持續改善

### 10.1 待補來源案件列管追蹤（Unresolved-Source Queue）
行政人員受理之佐證若判定為 `PENDING_SOURCE` 或 `HOLD_PRIVACY`，必須自動進入「待補列管清單」，實施動態週報控管：
- **追蹤週期**：每週一晨會盤點列管案件，對補正截止日前 7 日之案件發出自動催辦通知。
- **補正逾期處置**：自發出補件通知日起算屆滿 30 個日曆天仍未取得合規原件者，系統自動將狀態變更為 `REJECTED`，退出評核備選清冊。

### 10.2 原件調閱現場抽測與演練程序（Retrieval Stress Test）
為確保外部評核現場能於 3 分鐘內調出原件備查，本會每半年實施一次無預警調閱壓力測試：
1. 內部稽核員隨機抽取登錄表內 5 筆紀錄。
2. 文件管制員依循登錄表上之 `restricted_locator` 索引，於保險櫃取出實體卷宗；電子檔自 WORM 系統提取並現場跑 SHA-256 驗證。
3. 測試合格標準：實體取件時間不得超過 180 秒；雜湊比對必須百分之百吻合；個資遮蔽必須符合規範。

### 10.3 缺失分析與流程防呆回饋
針對審查駁回（`REJECTED`）與暫緩調閱（`HOLD_PRIVACY`）案件，品保小組應按季統計根本原因：
- 若「欠缺活動成效分母」比例偏高，應修正公益合作前置協議，將「成效量化簽收表」列入出勤必備交件清單。
- 若「個人資料未授權」頻繁發生，應全面修訂活動報名表，將個資告知暨授權條款嵌入報名表首頁。
