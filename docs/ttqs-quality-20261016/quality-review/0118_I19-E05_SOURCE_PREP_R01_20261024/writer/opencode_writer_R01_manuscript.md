**文件 ID：0118 ｜ 官方需求 ID：I19-E05 ｜ 版本：R01**

---

## 1. 文件用途、官方來源、證據效力及邊界

### 1.1 本文件是什麼

本文件是**可重複使用的收件登錄表、原件保管紀錄與核驗清單**，供協會授權的訓練行政承辦人逐件登錄實際收到的第三方來函，並由第二位指定覆核人確認。

主要讀者：

- **承辦角色**：協會指定的訓練行政承辦人，負責收件登錄與原件保管。
- **覆核角色**：協會指定的第二位覆核人，負責確認文件完整性、來源核驗與指標關聯。

> **角色聲明**：上述角色為**候選作職責描述**，不代表協會已任命任何人，也不代表協會已核准任何流程。實際任命與授權依協會正式程序辦理。

### 1.2 本文件不是什麼

- ❌ 不是感謝函範本，不提供可套用的信箋版型。
- ❌ 不代替感謝函原件；登錄表本身不構成第三方來函。
- ❌ 不是感謝函內容的轉錄本，不重製第三方函文。
- ❌ 不是正式接受、送審或核准文件。

### 1.4 證據效力與限制

感謝函**可以**作為官方檢核表列示的一種參考佐證。但是：

- 函件**不自動證明**訓練造成特定績效、服務結果或顧客價值提升。
- 感謝語句本身**不等於**因果成果。
- 無法辨認對象的截圖、與訓練無關的函件，**不得**推論為績效證據。
- 未取得原件或未能核驗來源時，**一律採 HOLD**，不得填成「已驗證」。
- 「可送人工審閱」**不是**協會正式接受；只有人類依正式規則決定，才能記錄接受或送審。

## 4. 判定矩陣（狀態、觸發條件與下一步）

| 狀態代碼 | 觸發條件 | 下一步 |
|---|---|---|
| `RECEIVED_PENDING_CHECK` | 已實際收到原件，核驗項目尚未全部完成 | 繼續逐項核驗；維持待檢，不得對外表述為已核驗 |
| `HOLD_NO_ORIGINAL` | **未取得任何原件**（僅有請求稿、轉述、空白稿或無件） | 取得原件前不得登錄為已收件／已核驗；啟動補件追蹤 |
| `HOLD_SOURCE_UNVERIFIED` | 已有原件，但來源身份未由獨立正式管道確認 | 以獨立管道續查；查證未完成前維持 HOLD |
| `HOLD_SCOPE_OR_PRIVACY_REVIEW` | 關聯範圍不明、缺頁附件、疑似修改、或個資／用途授權未釐清 | 補件或送隱私／範圍審閱；疑點確認前不採用 |
| `RETURN_FOR_SUPPLEMENT` | 缺件、缺頁、缺附件、內容不足以致無法判讀 | 開立補正事項、責任角色與期限，退回補件 |
| `ELIGIBLE_FOR_HUMAN_REVIEW` | **已取得原件**，且來源、完整性、關聯、隱私四項檢核**全部完成**，並經第二位覆核人檢視 | 送人工審閱；**此狀態不是正式接受** |
| `NOT_ACCEPTED_CONFIRMED_COPY_OR_MISMATCH` | 已確認為非原件、錯置文件、內容／發函者不符，或違反資料授權 | 寫明證據後拒絕採用；疑點**未**確認前不得使用本狀態 |

### 4.1 狀態流轉原則

1. `HOLD_NO_ORIGINAL` 是**唯一起點狀態**，用於一切缺件情形；在原件到達前不因任何補述而改變。
2. 原件到達後 → `RECEIVED_PENDING_CHECK` → 依核驗結果分流至各 HOLD、`RETURN_FOR_SUPPLEMENT` 或 `ELIGIBLE_FOR_HUMAN_REVIEW`。
3. `ELIGIBLE_FOR_HUMAN_REVIEW` **僅**表示可送人工審閱，**不是**協會正式接受；只有人類依正式規則決定才能記錄接受／送審。
4. `NOT_ACCEPTED_CONFIRMED_COPY_OR_MISMATCH` 僅在「已確認為非原件／錯置／不符／違反授權」時使用，並須寫明證據。**疑點未確認時不得寫成造假**，只能維持 HOLD 或 RETURN_FOR_SUPPLEMENT。

### 4.2 拒收、補正與保留條件

**HOLD（保留待處）**

- 沒有原件 → `HOLD_NO_ORIGINAL`；取得原件前不得登錄為已收件／已核驗。
- 只有截圖、轉寄、影本、空白稿 → 記錄**實際型態**並 HOLD；除非正式規則允許**且**來源已核實，否則不納入原件結論。
- 來源未獨立確認 → `HOLD_SOURCE_UNVERIFIED`。
- 內容關聯不明、缺頁附件、疑似修改、個資使用未釐清 → `HOLD` 或 `RETURN_FOR_SUPPLEMENT`。

**RETURN（補件）**

- 缺頁、缺附件、可讀性不足、內容無法判讀 → `RETURN_FOR_SUPPLEMENT`，須記錄補正事項、責任角色與期限。

**REJECT（不採用）**

- 僅在下列**已確認**情形標記 `NOT_ACCEPTED_CONFIRMED_COPY_OR_MISMATCH`：非原件、錯置文件、內容或發函者不符、違反資料授權。
- 必須寫明證據位置。
- 疑點**未**確認前不得寫成造假，不得標 NOT_ACCEPTED。

**絕對禁止**

- ❌ 不建立或補寫任何真實第三方原件、寄件紀錄、查證回覆、核准或簽章。
- ❌ 不因感謝語句而推論績效或成果。
- ❌ 未覆核不得視同核驗通過。

### 6.1 三層資料分層

### 6.2 保管鏈要求

1. **收件**：記錄實際收件方式、時間、件數與保管位置；無原件不建「已收件」紀錄。
2. **保全**：保留收到的原始位元組，不覆寫原檔；數位件計 SHA-256 並標明雜湊對象；紙本記錄封存索引／檔案盒編號。
3. **移交**：每次移交記錄移交時間、交出方角色、接收方角色；保管人變更須留紀錄。
4. **存取**：受限位置僅開放協會授權人員；存取權限本身亦屬受控欄位。
5. **對照隔離**：個資身份對照與聯絡紀錄**只**放受限位置，不得進入公開證據包。

### 6.3 隱私與使用限制規則

- 涉及個資、保密、同意或用途限制者，判定為 `HOLD_SCOPE_OR_PRIVACY_REVIEW`，直至釐清。
- 不適合公開的細節一律留在受限位置；公開層僅保留去識別化代碼與摘要。
- 未取得使用授權前，不得將函件內容納入任何對外資料。
- 違反資料授權且**已確認**者，方可標 `NOT_ACCEPTED_CONFIRMED_COPY_OR_MISMATCH`。

### 6.4 公開證據代碼規則

- 公開層僅使用去識別化證據代碼（例如依協會規則編配之代碼）。
- 代碼與受限資料之對照表**僅**存於受限位置。
